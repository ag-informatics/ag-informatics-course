# Module 5: User Interfaces

## About This Module

In this module, we'll learn the fundamentals of user interface design and development, while accounting for overally user experiences. The emphasis will be on learning how design and implement a cohesive and consistent user interfaces.

**1. Domain fluency: user interactions for agricultural user experiences**
Provide users with  the ability to better manage their data
* How can you translate user workflows into a defined set of domain-relevant user interaction?
* How do people elicit and translate domain-specific considerations into software designs?
* What makes a user interface design "good"?
* What are some examples of "good" ag-tech?
* Goal: Define and support appropriate human-computer interactions, with focus on what the user sees and does.

**2. Technical fluency: implementing user interfaces**
Implement user interfaces to support defined user interactions and experiences.
* How does one translate user interface ideas into implementable mockups?
* How can software specifications guide implementation (cont.)?
* What is component-driven design?
* How do developers implement and maintain consistent user interfaces?
* Goal: Upgrade a small Django web application, with focus on Django views and templates, using the Boostrap framework and CSS to implement a design system.

## Rubrics

Total: 30 (5 in-class activity + 5 quiz + 20 lab).

### In-class activity (Lecture 5.2) — 5 pts

The TA-led design activity: the journey map with its use case circled, and the paper prototype of 4 views.

| Points | Criteria |
| --- | --- |
| 0 | Missed |
| 2 | Incomplete — doesn't have to be "right" |
| 5 | Complete - doesn't have to be "right"! |

### Quiz 5 — 5 pts

An individual, on-paper heuristic evaluation in Lecture 5.4: a cognitive walkthrough of an ag-tech tool, guided by Norman's principles of design and one criterion of your own.
<!-- See [quiz-5-heuristic-evaluation/](quiz-5-heuristic-evaluation/README.md). -->

### Lab 5 — 20 pts

* Git Commits — 4 pts
    * 1 pt for each of 4 commits.
* Spec kit: overview, use case and views — 4 pts (STEPs 0-2)
    * `spec-kit/SPEC.md` sections 0-3: system overview, user and use case, the 4 views with their menu options and use-case steps, and the paper prototype of each view.
* Design system and mockup — 4 pts (STEPs 3-4)
    * `SPEC.md` sections 4-5: a light design system (palette, typography, assets) and one mockup of their most complex view, in their design tool.
* Implementation — 8 pts (STEPs 5-6)
    * 4 implemented views (2 basic, 1 form, 1 advanced), using Bootstrap components and styled to the design system.
