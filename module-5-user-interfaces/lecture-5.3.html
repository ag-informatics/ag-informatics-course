Django's template design principles


  • Separate logic from presentation: query, filter and sort in views.py. Templates only loop, branch, and lay it out.

  • Discourage redundancy: a sitewide header, footer and navbar live "in a single place": template inheritance.

  • Safety and security: templates can't run arbitrary Python, and {{ }} escapes what users type.

Farmnotes demo with UI upgrades

Same models and data as Module 4. Code: the Bootstrap + Django demo.

Parent template:
base.html, the head

  • Bootstrap's CSS from a CDN (line 9).
  • Then your style.css: it loads second, so your design system wins.

Parent template:
base.html, the navbar

  • A Bootstrap navbar component, in a container.
  • Its links use {% url %}: by route name, not typed-out paths.

Parent template:
base.html, the body
  • {% block content %} is the hole each page fills in.
  • A footer, shared by every page.
  • Bootstrap's JavaScript, at the bottom: the navbar's collapse button needs it.

A page: index.html

  • {% extends %} pulls in base.html; the page fills only {% block content %}.
  • Bootstrap's grid: a row, and a col per card (col-lg-4 = 4 of 12 columns).
  • {% include %} drops in one component per field.

A component: _card.html

  • A Bootstrap card, written once, reused on any page that has a field.
  • The underscore in _card.html marks it as a piece, not a page.
  • {% url 'notes' field.id %}: a link by route name, not a typed-out path.

Result: http://127.0.0.1:8000/farmnotes/

Named URLs:
farmnotes/urls.py

  • Each route has a name. Templates link with {% url 'notes' field.id %}.
  • Change a path here, and every link still works.

Components: notes.html

  • A Bootstrap list group: each observation is a link.
  • {% empty %} covers a field with no observations yet.
  • A Bootstrap button into the form.

Result: http://127.0.0.1:8000/farmnotes/1/

Result: http://127.0.0.1:8000/farmnotes/1/1/

Codified design:
static/farmnotes/style.css

  • Bootstrap reads its colors and fonts from CSS variables (--bs-...)
  • Set a variable once, and every component that uses it changes.

Forms: enable user input

  • A form page is visited twice.
  • GET: the user arrives, and the view shows an empty form.
  • POST: the user submits. The view checks the data, saves it, and redirects; if the data isn't valid, the same page comes back with the errors.

Build forms on models:
farmnotes/forms.py

  • A ModelForm builds its fields from the Observation model.
  • fields: what the user fills in. The field comes from the URL, so it isn't on the form.
  • widgets: gives each input Bootstrap's form-control class, and a date picker.

Handle GET and POST:
farmnotes/views.py

  • request.method == 'POST': the user submitted.
  • is_valid() checks the data; save(commit=False) lets the view attach the field first.
  • redirect() back to the notes page, by route name.

Form template: observe.html

  • method="post": the form sends data.
  • {% csrf_token %}: Django checks the form came from this site.
  • Without it, the POST is refused.
  • Each field gets a Bootstrap label and input, and its errors.

Result: http://127.0.0.1:8000/farmnotes/1/observe/
