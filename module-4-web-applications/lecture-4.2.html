When Django breaks

Modules 3-5: AI for debugging and exploring only.

  • Read the error: the last line says what, the lines above say where.
  • Search it: the Django docs, Stack Overflow.
  • Then ask an AI, to understand, not to fix.

Write the question first

  • What I expected, and what happened: paste the full error.
  • The smallest code that still breaks, and its file: views.py, urls.py, settings.py.
  • What I already tried.

Stack Overflow, How do I ask a good question? and How to create a minimal, reproducible example.

Ask to understand, then verify

  • Ask "why is this failing?", not "fix this".
  • Ask for a reference you can check, like the Django docs.
  • Change one thing, rerun, and keep only what you understand.

Keep a debugging log

  • One entry per bug: the error, what I tried, what fixed it.
  • Save the prompts and answers you used.
  • Disclose your AI use in your lab README.

Django models:
farmnotes/models.py

The same Python class translated into Django model.

  • In Django, a MODEL describes the structure of your data, as well as your database.
  • Since models are written in python, we are essentially creating python OBJECTS, or CLASSES,
    that Django processes and converts into the database itself.
  • FIELD_TYPES and OBSERVATION_TYPES are lookup lists defined above the classes (see the demo).

Update models, migrate to DB

  1. Edit your models in the file models.py

  2. python manage.py makemigrations farmnotes to stage the migration to reflect model changes.

  3. python manage.py migrate to push the changes to the database.

You can think of makemigrations as the Django version of git add and git commit,
where you are simply indexing the changes you'd like to make. migrate is like the Django equivalent of git push -- it actually makes the changes you desire.
